## 贡献流程

### 1. Fork 并克隆仓库

```bash
# Fork 本仓库后，克隆你的 Fork
git clone https://github.com/你的用户名/legado-sources.git
cd legado-sources

# 添加上游仓库
git remote add upstream https://github.com/原作者/legado-sources.git
```

### 2. 创建功能分支

```bash
git checkout -b feature/你的分支名
```

分支命名建议：
- 新增书源：`feature/source-站点名`
- 修复书源：`fix/source-站点名`
- 新增净化源：`feature/purge-名称`
- 工具改进：`feature/tool-功能名`
- 文档更新：`docs/更新内容`

### 3. 进行修改

将你的书源文件添加到对应目录：

```
bookSources/legado/fiction/      # Legado 小说书源
bookSources/legado/comics/       # Legado 漫画书源
bookSources/legado/audiobooks/   # Legado 有声书源
purgeSources/legado/             # Legado 净化源
subscribeSources/legado/         # Legado 订阅源
```

### 4. 运行校验

**提交前必须运行校验工具，确保格式正确：**

```bash
python3 tools/validate.py 你修改的文件或目录
```

示例：
```bash
python3 tools/validate.py bookSources/legado/fiction/biquge.json
```

### 5. 提交更改

```bash
git add .
git commit -m "提交信息"
```

提交信息格式：
```
[类型] 简要说明

详细说明（可选）
```

类型选项：
- `[新增]` - 新增书源/净化源
- `[修复]` - 修复失效或错误的源
- `[更新]` - 更新已有源的规则
- `[移除]` - 移除失效源
- `[工具]` - 工具脚本改进
- `[文档]` - 文档更新

示例：
```
[新增] 添加笔趣阁书源

- 包含搜索、详情、目录、正文规则
- 支持发现页分类浏览
- 已通过 validate.py 校验
```

### 6. 推送并创建 PR

```bash
git push origin feature/你的分支名
```

然后在 GitHub 上创建 Pull Request，填写 PR 模板中的内容。

## 书源提交规范

### 文件命名

- 使用小写英文，多个单词用连字符 `-` 分隔
- 以站点名或主题命名，如 `biquge.json`、`qidian.json`
- 避免使用中文文件名

### 文件内容

- 每个文件建议包含同一网站的多个书源（不同分类/线路）
- 或包含同一主题的多个站点书源
- 文件必须是合法的 JSON 数组
- 编码必须为 UTF-8

### 书源字段规范

**必填字段：**
- `bookSourceName`：书源名称，建议包含站点标识
- `bookSourceUrl`：站点主页 URL
- `bookSourceType`：0=文本, 1=音频, 2=图片, 3=文件
- `searchUrl`：搜索 URL 规则
- `ruleSearch`：搜索结果解析规则
- `ruleBookInfo`：书籍详情解析规则
- `ruleToc`：目录解析规则
- `ruleContent`：正文解析规则

**推荐填写：**
- `bookSourceGroup`：书源分组，便于管理
- `bookSourceComment`：书源备注，说明特点或注意事项
- `enabledExplore`：是否启用发现页
- `lastUpdateTime`：最后更新时间戳（毫秒）

### 质量要求

1. **可用性**：提交的书源应能正常搜索和阅读
2. **完整性**：搜索、详情、目录、正文四个规则都应配置
3. **准确性**：解析规则应能正确提取对应内容
4. **无侵权**：不提交明显侵权或违法的书源

### 失效书源处理

如果发现书源失效：
1. 先确认是网站本身问题还是规则过期
2. 如能修复，提交 `[修复]` PR
3. 如无法修复，提交 Issue 或 `[移除]` PR，并在备注中说明原因

## 净化源提交规范

### 规则编写原则

1. **精准**：正则表达式应精准匹配目标内容，避免误删正文
2. **通用**：尽量编写适用于多个站点的通用规则
3. **注释**：复杂规则应在 `comment` 字段说明用途

### 测试要求

提交净化源前，请在至少 2-3 个不同网站的正文中测试，确保：
- 广告内容被正确去除
- 正文内容不受影响
- 不会导致页面空白或乱码

## 代码贡献规范

### Python 代码

- 遵循 PEP 8 规范
- 使用 4 空格缩进
- 函数和变量使用 snake_case
- 添加必要的注释和文档字符串
- 兼容 Python 3.7+

### 工具脚本

- 放在 `tools/` 目录下
- 必须支持 `--help` 查看用法
- 有清晰的错误提示
- 不引入第三方依赖（标准库即可）

## PR 审核标准

你的 PR 会从以下方面审核：

| 维度 | 标准 |
|------|------|
| **格式** | JSON 语法正确，通过 validate.py 校验 |
| **完整** | 必填字段齐全，解析规则完整 |
| **可用** | 书源能正常使用（维护者会抽查） |
| **规范** | 文件名、提交信息符合规范 |
| **安全** | 不包含恶意代码、侵权内容 |
| **文档** | 如有必要，更新相关文档 |

审核通过后，维护者会合并你的 PR。如有问题，会在 PR 中留言说明。

## 常见问题

**Q: 我可以提交需要登录/付费的书源吗？**
A: 可以，但请在 `bookSourceComment` 中明确说明需要登录或付费，并启用 `enabledCookieJar`。

**Q: 提交后多久能审核通过？**
A: 一般在 1-3 个工作日内审核。如果 PR 有问题会及时反馈。

**Q: 我的书源被拒绝了怎么办？**
A: 审核意见会写在 PR 评论中，根据意见修改后重新提交即可。

**Q: 可以批量提交多个书源吗？**
A: 可以，但建议按站点或主题分成多个文件，每个文件单独校验。

**Q: 如何获取书源规则的写法？**
A: 参考 `templates/` 目录下的模板，以及已有书源文件的写法。也可以参考 Legado 官方文档。
